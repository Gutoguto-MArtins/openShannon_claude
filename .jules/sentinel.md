## 2025-05-28 - [Command Injection in `which` logic]
**Vulnerability:** A command injection vulnerability existed in the `whichNodeAsync` helper function (found in `src/utils/which.ts`). It used `execa(\`which ${command}\`, { shell: true })` and `execa(\`where.exe ${command}\`, { shell: true })`. This meant any `command` string that contained shell operators (e.g., `; touch pwned`) would be evaluated by the shell, leading to execution of arbitrary shell commands.
**Learning:** Even seemingly "safe" built-in tools like `which` or `where.exe` must be invoked carefully. If any part of the command text could be controlled by user input or an unpredictable source, using Node's `child_process` execution capabilities with `shell: true` exposes the system to command injection risks because the underlying shell naturally expands parameters and interprets control operators.
**Prevention:** Always default to invoking commands using array arguments with `{ shell: false }` (e.g., `execa('which', [command], { shell: false })`). The arguments array ensures that operators and meta-characters are treated exactly as string arguments by the executable itself, and never interpreted by the shell. Avoid string concatenation when building commands to execute.
