## 2025-02-27 - Prevented Command Injection in which.ts
**Vulnerability:** The `which` utility functions (`whichNodeAsync` and `whichNodeSync`) used `execa` and `execSync_DEPRECATED` with string interpolation and `{ shell: true }` (or implicit shell usage) to search for binary paths. If an attacker provided a crafted command string containing shell metacharacters like `;`, `|`, or `&&`, arbitrary code execution would occur in the context of the user running Claude Code.
**Learning:** Shell command injection is a systemic risk whenever user or external input is directly injected into shell strings. `execa` and `execSync_DEPRECATED` functions should avoid the `shell: true` option unless strictly necessary for invoking actual shell mechanisms safely, and they definitely should not interpolate variables directly into the command string.
**Prevention:** Always use arrays of arguments to `execa` and `execaSync` (or native `child_process` equivalents) to guarantee that inputs are passed strictly as arguments to the spawned binary rather than evaluated by a shell. By passing `['which', command]` and `{ shell: false }`, we completely close off command injection possibilities while retaining exact expected behavior. Additionally, avoid legacy wrappers like `execSync_DEPRECATED` when modern alternatives like `execaSync` are available.
