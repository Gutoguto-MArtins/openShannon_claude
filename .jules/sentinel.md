## 2025-02-06 - Prevent Command Injection in which.ts
**Vulnerability:** The `which.ts` module dynamically interpolated arbitrary user inputs into `execa` commands executing with `shell: true` and the deprecated `execSync_DEPRECATED` wrapper. This exposed the application to command injection attacks because any shell meta-characters provided in the `command` variable (e.g. `node; rm -rf /`) would be executed by the shell.
**Learning:** Utilities that execute dynamically generated shell commands to discover file paths are a frequent source of command injections. Specifically, the synchronous fallbacks and Windows support paths need to be scrutinized just as much as primary code paths.
**Prevention:** Remove `shell: true` and any synchronous wrappers relying on native `execSync` execution. Instead, utilize `execa` for async logic and `execaSync` for sync logic with `shell: false`, and always pass dynamic input values individually as entries in an array argument list rather than concatenating them into a single command string.
