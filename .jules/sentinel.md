## 2023-10-24 - [Command Injection via String Interpolation in which/where.exe]
**Vulnerability:** The `src/utils/which.ts` module previously used string interpolation (`which ${command}`) with `shell: true` or `execSync_DEPRECATED` when querying for executable paths. This introduced a command injection vulnerability where a maliciously crafted command name could break out of the string and execute arbitrary shell commands.
**Learning:** Even when performing common system checks like looking up executable paths, passing user-controlled variables directly as string literals into shell execution contexts without proper quoting or using `shell: false` opens up command injection vectors. The codebase uses `execSync_DEPRECATED` which acts as a wrapper around the native Node.js `child_process.execSync` and utilizes a shell by default.
**Prevention:** To prevent command injection during process execution, always avoid using `shell: true` and string interpolation. Instead, use a safe async alternative like `execa` or a sync alternative like `execaSync` with `shell: false` and pass command-line arguments as an explicit array (e.g., `execa('which', [command], { shell: false })`).
